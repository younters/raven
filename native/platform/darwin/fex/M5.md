# M5: x64 engine parity checkpoint

2026-10-30. Not full engine parity. Notepad++ reaches its editor under both
engines. Steam previously reached its updater but lacks the native DXMT unixlib
bridge; CEF/D3D11 and Chrome remain unqualified. FEX is not the default.

## Review dispositions

1. **Fixed:** x86 children of FEX parents explicitly use Rosetta until M4 WoW64
   lands. PE64 children inherit FEX. The child image is inspected before spawn.
2. **Fixed:** prefix-setup regsvr32 re-exec inherits the selected execution engine.
3. **Fixed:** free preferred bases are accepted at any address, including fixed
   PE64 images. Initial image ranges are atomically reserved during loader
   preflight, before FEX/dyld initialization
   and replaced only by their owned shared mappings. The high arena is fallback
   space. Runtime LoadLibrary already uses `process.memory_available` and the
   same ModuleSet fallback setting; it now agrees with startup. The diagnostic
   says the preferred base is unavailable, without assuming a host collision.
   `native_fixed_image_preferred_fex` exercises a relocation-free PE at
   0x8000000000 (below the 1 TiB fallback arena).
4. **Fixed:** alignment emulation has a thread-local recovery frame. A nested
   SIGSEGV/SIGBUS restores the original native context and redispatches as a
   guest AV. Guest exception callbacks clear the recovery pointer before leaving
   nonlocally. The write-AV fixture requires a catchable AV for an unaligned
   qword write to PAGE_NOACCESS (a whole 16 KiB host page).
5. **Verified:** OvercommitTracker handles only its registered internal intervals.
   A reserved-but-uncommitted guest write is required to raise a catchable AV by
   the same write-AV fixture; the general tracker call remains necessary for
   internal lookup-cache pages.
6. **Fixed:** INT 2D recognition requires a breakpoint, exact parameter count and
   service value, RAX=1, executable canonical bytes, and active API traps. It
   normalizes FEX's advanced PC only when fault conversion will occur. A direct
   debug-print probe exercises completion in cooperative and parallel modes.

The four original NT-service/alignment entries are FEX-only, now named `fex_*`.
Two additional FEX-only INT 2D checks were added. They are excluded from the
cross-engine count. Context assertions no longer accept alternative outcomes:
unsupported full-context classes must fail explicitly, and running-thread
ERROR_INVALID_PARAMETER checks are restored. Rosetta currently fails the first
running-thread check; its later SetThreadContext is also unimplemented. The
strict native context test is an expected failure pending the **upstream-merge**
branch's Darwin SetThreadContext work. It is never counted as a successful pair.
The fixture target is a dependency of both Raven and the parallel fixtures.

The old mixed commit `6dcb67e` was left intact to avoid rewriting reviewed history.
All new changes are separate local commits. Nothing was pushed.

## DXMT implementation options and remaining work

Source inspection: guest/agent.c loads `__wine_unix_call_funcs`, validates the
adapter protocol, calls `raven_unixlib_init` and `raven_unixlib_wrap_table`, and
retains each library for process lifetime. guest/unix_call.s bridges Win64 to
Darwin x86_64, preserving guest state. Neither that machine code nor the x86_64
unix64/winemetal.so can execute as a native FEX-host library.

The feasible route is an additional **arm64 unixlib overlay**, leaving pe64 DLLs
as x64: build_source.py must select native compiler `-arch arm64`, a separate
Meson output and adapter path (for example unix-arm64/), keeping the pinned
132/146-entry table contract. DarwinUnixCalls must choose that overlay for FEX.
FexProcess then needs a guest-visible Win64 dispatcher that stops at a reserved
trap, validates the handle/index and calls the arm64 table on an appropriate
native stack. It must preserve guest context and exception state and handle
blocking/native callbacks without violating controller ownership.

A library loader alone is insufficient: the native adapter also needs a live
raven_control-compatible presentation/event structure, drain_unix_events and
resume/pump integration, darwin_control forwarding, and same-process Mach send
right retention in copy_unix_port. Presentation slots/IOSurfaces and completion
NtSetEvent callbacks must work on the Cocoa main loop. unix_adapter.m and
presentation.m contain these contracts. No native arm64 overlay or dispatch
bridge was implemented or silently substituted in this checkpoint.

Remaining milestones: implement and qualify that bridge, real served/queued
calls, native callback ownership, timers and CEF/V8 memory/SMC behavior; run Steam
to CEF and D3D11 against a qualified Rosetta baseline, then Chrome; add those app
contracts and workload benchmarks. Broader Windows and full NativeProcess parity
remain open. Do not make FEX the default based on this checkpoint alone.
