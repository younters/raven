# M5: real x64 applications — implementation checkpoint

2026-10-30. **Not full engine parity.** Notepad++ reaches its editor under both
engines. Steam reaches its update window and child launches under FEX, then
reports the missing DXMT unixlib host. CEF/D3D11 parity is not qualified. Chrome
was not run. No push, merge into macos, debugger attachment, or attribution trailer.

Branch `t3/fex-engine-parity`, rebased onto macos `703c4fe`. The local commits
separate process handoff, frontend fault repair, parity registration and benchmarks.

## Implemented

- Capture syscall number per guest thread, expose orig_rax and validate the exact
  SYSCALL/RET boundary before entering an NT service. Restore RCX from R10 and
  clear pending syscall state. Verify mismatched numbers are rejected without
  consuming the stop; return 42 through the real guest return gate in cooperative
  and resident-worker execution.
- Canonical INT 2D debug-print completion, with captured-stop validation. This
  path has code coverage by inspection, not a dedicated executed INT 2D probe.
- Inherit `--execution=fex` on child launches through a thin Darwin launch seam.
  Steam's child launches use this selection; arbitrary process-tree parity is not
  claimed. RAVEN_FEX_MODULE_ROOT is inherited through the normal environment.
- Keep PE64 images in the high image arena: a low preferred base could be free
  during loader preflight and occupied after FEX/dyld initialization. Fixed images
  outside the policy still fail explicitly; this is not a reservation protocol.
- Distinguish Darwin alignment SIGBUS by ARM ESR fault status (0x21), rather than
  trusting si_code alone. Other SIGBUS faults remain AVs. Restore FEX's existing
  unaligned-access and overcommit handlers before guest exception reconstruction.
  The first real-app failure was a valid unaligned qword store; the next was an
  internal L1 lookup-cache store to a reserved, not yet committed page.
- Enable JIT backpatch writes during synchronous fault repair, preserving prior
  thread mode on normal return. Existing worker/controller nonlocal stop paths
  restore their saved JIT mode. General signal async-safety remains unqualified.

The new frontend patch is `0013-raven-unaligned-tso.patch`. Module source was
cloned privately from the shared component tree, then unrelated M4 changes were
removed from that private copy. The final source tree is exactly the pinned
13-patch series (verified with a private Git index); its ARM64EC binary hash
remained identical after removing those unrelated changes. The shared component
installation was never overwritten. PE audit and source-tree proof are in
[m5/module.json](m5/module.json).

## DXMT implementation options and remaining work

Source inspection: guest/agent.c loads `__wine_unix_call_funcs`, validates the
adapter protocol, calls `raven_unixlib_init` and `raven_unixlib_wrap_table`, and
retains each library for process lifetime. guest/unix_call.s bridges Win64 to
Darwin x86_64, preserving guest state. Neither that machine code nor the x86_64
unix64/winemetal.so can execute as a native FEX-host library.

The feasible route is an additional **arm64 unixlib overlay**, leaving pe64 DLLs
as x64: build_source.py must select native compiler `-arch arm64`, a separate
Meson output and adapter path (for example unix-arm64/), keeping the pinned
132/146-entry table contract. DarwinUnixCalls must choose that overlay for FEX.
FexProcess then needs a guest-visible Win64 dispatcher that stops at a reserved
trap, validates the handle/index and calls the arm64 table on an appropriate
native stack. It must preserve guest context and exception state and handle
blocking/native callbacks without violating controller ownership.

A library loader alone is insufficient: the native adapter also needs a live
raven_control-compatible presentation/event structure, drain_unix_events and
resume/pump integration, darwin_control forwarding, and same-process Mach send
right retention in copy_unix_port. Presentation slots/IOSurfaces and completion
NtSetEvent callbacks must work on the Cocoa main loop. unix_adapter.m and
presentation.m contain these contracts. No native arm64 overlay or dispatch
bridge was implemented or silently substituted in this checkpoint.

Remaining milestones: implement and qualify that bridge, real served/queued
calls, native callback ownership, timers and CEF/V8 memory/SMC behavior; run Steam
to CEF and D3D11 against a qualified Rosetta baseline, then Chrome; add those app
contracts and workload benchmarks. Broader Windows and full NativeProcess parity
remain open. Do not make FEX the default based on this checkpoint alone.
