# M2: opt-in FEX execution

Branch: `t3/add-fex-execution-backend`. Work in progress; M2a is not complete.
Rosetta remains the default. No push, entitlement or system changes.

The first checkpoint extracts M1d initialization for reuse, then runs a real PE
entry through an arm64 FexProcess. Provider INT3 delivery is the next gate:
M1d qualifies SYSCALL and read AV, not Raven's breakpoint provider convention.
The existing NativeProcess is a concrete class, not a virtual backend interface;
its runtime selection and stopped-frame semantics need a thin Darwin seam.

Tests and reproduction commands will be recorded with the implementation.

## Checkpoint 2: stopped-context engine (M2a INCOMPLETE)

`FexProcess` now reuses M1d attach/init, maps real PE64 bytes at their guest
addresses, supplies a guest stack and returning syscall gate, and transfers
syscall/AV stops back to its native caller. It translates the AMD64 packet to
`NativeContext`, applies caller edits and resumes through BeginSimulation.
The exception record is copied without allocation before nonlocal transfer;
exception-information vectors are constructed only after returning to the owner.

The CLI seam currently supports **`--run-entry --execution=fex` only** in an
opt-in `RAVEN_FEX_MODHOST=ON` build. `--run-process --execution=fex` is NOT
implemented. FexProcess does NOT yet implement/delegate the full NativeProcess
interface. No kernel32/NT process fixture, thread fixture or SEH fixture has passed.
**There is no qualified `Native entry returned 0` M2a result.** The zero printed
by the divide-negative CLI probe is a WRONG RESULT, retained as failure evidence.

### Named blockers: M2-EXCEPTION-DELIVERY and M2-DIVIDE-ERROR

The final `fex_process_test ... breakpoint` probe (actual `CC C3` bytes, the
provider breakpoint convention) exits **-5 / SIGTRAP**, without a NativeResult.
The current signal scope only installs SIGSEGV/SIGBUS. A local experiment routing
SIGTRAP as STATUS_BREAKPOINT reconstructed RIP at entry+1, but was reverted:
blindly classifying every FEX BRK as a guest breakpoint is not correct. The host
must consume FEX synchronous-fault metadata and distinguish guest breakpoints,
illegal instructions, divide errors and internal/native failures. The existing
RavenHandleFault export only qualifies the AV reconstruction path.

More seriously, the exact diagnostic bytes
`31 c9 b8 01 00 00 00 31 d2 f7 f1 c3`
(`xor ecx,ecx; mov eax,1; xor edx,edx; div ecx; ret`) **return zero without any
exception**. The same PE bytes under Rosetta stop with **signal 8 / SIGFPE** at
entry+9. The diagnostic test correctly fails with `divide error misclassified`;
this is not marked WILL_FAIL or counted as a passing contract. The pinned FEX
`FEXCore/Source/Interface/Core/JIT/ALUOps.cpp::UDiv` emits ARM64 UDIV without a
zero-divisor check, including its optimized no-upper-input path. The IR DIV
frontend similarly has no zero check. No host-only signal adapter can recover an
exception that was never emitted. The existing `kernel_seh_client.c::divide(0)`
requires this behavior. A new isolated FEX patch, module rebuild/pin update and
precise fault regressions are required before claiming the exception contract.

### Remaining implementation after the blockers

1. Patch and qualify precise INT3/UD2/divide delivery, register the qualification
   probes as ordinary passing tests only once their actual expectations pass.
2. Introduce the Darwin NativeProcess runtime-selection seam; preserve Rosetta
   defaults. Connect guest TEB/PEB/GS to NativeEnvironment rather than using only
   the module's private hosting environment. External TEB replacement currently
   fails explicitly. Connect provider trap lookup, API arguments/results, fault
   stops and Raven SEH dispatch; leave served pointers zero to use real traps.
3. Connect shared LoadedImage storage and dynamic map/protect/unmap/invalidation,
   guest access validation and the documented Tier 0 coarse-page policy. Current
   engine copies images to RW guest data mappings and is not a Windows VM policy.
4. Qualify callbacks, complete FP/XSTATE, module/thread destruction, signal-safe
   handoff and doorbell deadlines. Current engine allows one process lifetime per
   host, on one host thread, four entry arguments, no timeout/parallel/callback
   contract. It retains the module for host lifetime. The temporary embedded
   harness source should become a dedicated substrate unit before widening use.
5. Run a real kernel32 console fixture through process initialization to verified
   zero exit, then threads and SEH, then time the same process fixtures.

WoW64 and DXMT were not built or integrated. M1d native workers still lack FEX
ThreadInit/ThreadTerm. The Rosetta unix-call gate executes Darwin syscalls and
switches GS/TSD; it must not be reused as x64 Windows code under FEX. M4/M5 need
separate guest syscall gates and native arm64 unix-library dispatch.

## Continuation: exception gates are implementation work

The two earlier named blockers are being fixed here; neither is an external

inspection performed before writing patch 8. There was no applicable upstream
correctness fix or configuration switch to port. Patch 8 adds Raven-gated

and consumes FEX's generated-fault metadata through its Windows classifier.
The signal scope now installs SIGTRAP/SIGILL as well as AV handlers, with rollback
if any handler installation fails. Native/internal faults are rejected before
host exception callbacks rather than relabelled as guest breakpoints.

### Tier 0 PE placement policy

FEX x64 guests use host-visible addresses. Preferred bases such as `0x140000000`
can overlap the arm64 executable/dyld cache; `0x400000` also falls inside the
arm64 executable's mandatory PAGEZERO reservation. Reservation must use fixed
Mach allocation **without overwrite** and must never replace a host mapping.
Try a free preferred base where possible. If it is unavailable and the PE has a
valid base-relocation directory, reserve an aligned free high range and construct
LoadedImage at that actual base, applying its ordinary checked DIR64 relocations.
The module graph/IAT must use those actual bases before binding. The initial
entry seam chooses `0x10000000000` for relocatable images; the process loader must
extend this to a collision-checked arena for the whole graph and dynamic loads.
An image without relocations must execute at its preferred base or fail with an
explicit address-conflict diagnostic. It must not be silently rebased, and bytes
must not be interpreted as position-independent merely because a test happens
to use RIP-relative instructions. PE32/`0x400000` guest-window support is M4.
