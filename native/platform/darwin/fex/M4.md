# M4: WoW64 module host and Tier 0 guest window

Protocol and implementation, 2026-10-30, on
`t3/fex-wow64-guest-window`. Qualification below distinguishes execution evidence
from remaining limits. Rosetta remains the default execution engine.

## Module and context protocol

Select exactly one frontend per Windows process: PE32 uses native ARM64
`xtajit.dll`; PE32+ uses the existing ARM64EC `xtajit64.dll`. Do not initialize
both FEX contexts in the same process. Retain the existing process-lifetime
mapping/single-init restriction. ARM64 exports use direct RVAs, never CHPE lookup;
imports still need Windows ARM64 to Darwin argument and x18 adapters. Static TLS
and the private native TEB remain separate from the Windows guest TEB32.

Use a separate, versioned `RavenWow64HostV1` table and `RavenWow64ProcessInit`
export. Do not reinterpret RavenHostV1's AMD64 packet as WOW64_CONTEXT. The new
table supplies a nonzero, 4 GiB-aligned guest base, per-thread WOW64_CONTEXT and
TEB32 lookup, native dispatch/exception callbacks, JIT hooks and logging. Validate
size/version/flags and all required pointers before initialization. Reject Tier 1
and hardware TSO requests in this milestone. Context packets use the pinned
716-byte WOW64_CONTEXT, including the 512-byte FXSAVE area; Darwin signal state
uses the existing ARM64 context translation. No exception may cross callbacks.

`BTCpuThreadInit` creates translation state on the resident thread. A Raven entry
export loads its host-owned WOW64_CONTEXT, sets the software segments, and enters
`RavenWow64Run`, which calls ExecuteThread without Wine's native-context capture/unwind frame. On a host stop, spill the complete guest packet and release the
frontend JIT-context lock before transferring to Raven's stop frame. Resuming
reloads the edited packet; do not abandon a live C++ lock by longjmp. The original
Wine BTCpu entrypoints remain available in non-Raven builds.

## Address domains and placement

Every public NativeProcess address is a **guest VA**, including EIP, ESP, FS base,
API arguments, exception addresses, allocation results and image bases. Reserve
an inaccessible, 4 GiB-aligned 4 GiB host window at B above PAGEZERO. Commit host
backing at B+g for guest address g; never relocate a PE32 image to B+g. PE32
relocations/IATs retain 32-bit values. Reject range overflow before adding B.
Guest zero and the first 64 KiB stay inaccessible. Windows allocations and image
bases use 64 KiB granularity; logical protections use 4 KiB pages, with M2's known
16 KiB host enforcement limitation and PAGE_GUARD rejection.

PE32 images retain preferred addresses where free, otherwise relocate within the
guest window. The ModuleSet availability callback must check window occupancy,
not the host's low PAGEZERO, and must never use the x64 high relocation start.
Stacks, return gate, heaps, TEB32, PEB32, TLS and process parameters all allocate
below the guest limit (initially 2 GiB, matching the existing x86 allocator).
KUSER_SHARED_DATA is backed at B+0x7ffe0000. Shared image descriptors have separate
host aliases for the loader; only window pages are exposed to translated code.

Memory ownership stays with Raven. Reserve once, replace only owned window
subranges when mapping descriptors, and restore PROT_NONE reservation holes on
release. Module-native allocations, emulator stacks and MAP_JIT caches stay
outside the guest window. Memory notifications take **host** addresses B+g,
matching WOW64 Module.cpp's InvalidationTracker(GuestBase); context/API packets
always take guest addresses. Audit each notification to avoid double rebasing.

## FS, APIs, exceptions and threads

NativeEnvironment's existing x86 constructor owns TEB32/PEB32 layout. Its FS base
is the guest TEB32 VA. Set a software GDT FS descriptor (selector 0x53, distinct from the flat data selector 0x2b) and
fs_cached to that VA; do not install Darwin LDT entries. The module's private x18
TEB supplies CRT/TLS only. Replace GetWowTEB's signed private TEB offset and
RtlWow64GetCurrentCpuArea with host-table lookups.

Keep existing PE32 INT3 provider stubs and their callee-cleanup metadata. Convert
the reconstructed guest breakpoint to NativeStop::api at the registered guest
address. NativeProcess::api_arguments reads 32-bit stack words at ESP+4;
return_api writes EDX:EAX and pops the return address plus registered stdcall cleanup.
Cdecl cleanup stays with the caller. Reuse run_native_process_x86,
NativeX86System/Thread/Compat and the shared API registry; do not invoke Wine
Wow64SystemServiceEx or recreate its syscall-number tables. A dedicated INT 2e
return gate can stop entry fixtures; unexpected INT 2e fails explicitly.

Fault reconstruction uses FEX's WOW64 state conversion and guest-window address
normalization. Preserve access kind, NT status, EIP/ESP, integer/flags and FXSAVE
state. The existing x86 runner forwards software RaiseException/RtlUnwind to the
32-bit runtime component; hardware-fault dispatch needs an explicit x86 exception
bridge before claiming hardware SEH parity. Never feed an x86 packet into the
x64 unwind dispatcher. Unhandled faults remain failures with guest diagnostics.

Reuse M3 resident workers and controller-owned NT scheduler: one private module
TEB/TLS and WOW64_CONTEXT per worker, stable across stops; all APIs run on the
controller. Pause/join before freeing a guest stack/TEB. Doorbell state and
context edits must target the selected worker, and nested callbacks must retain
per-entry guest packets. Qualify cooperative entry first, then process APIs,
then parallel threads, exception repair and code modification.

Host writes to executable guest ranges notify the frontend with B+g. Guest SMC
uses the existing invalidation tracker and fault reconstruction; protection and
release notifications bracket actual mapping changes. Test host patch/resume and
guest rewrite/execute separately. No 4 KiB protection or concurrent SMC parity is
inferred from successful entry.

## Required Raven-owned frontend patches

Enable Raven hosting for WOW64 independently of ARM64EC. Add the typed host table,
init/entry/fault exports, explicit host context/TEB lookup and context spill/resume
boundary. Bypass Wine loader-image discovery, class-1010 guest-base query,
WOW64INFO/TLS assumptions, syscall bridges, NtContinue/NtRaiseException and private
exception-dispatch stack layouts in Raven mode. Keep real allocator, tracker and
CPU feature setup with software TSO and native MAP_JIT hooks. Do not modify FEX's
translator simply to accommodate Raven address ownership. Preserve the existing
xtajit64 build/hash contract while adding xtajit-specific qualification.

## Implementation and evidence

The implementation selects xtajit.dll only for NativeMode::x86, reserves the
window before module init, maps PE descriptors at B+guestVA and retains low
relocation/IAT values. It uses a separately negotiated 112-byte host table
containing RavenHostV1 plus TEB32 lookup. In this negotiated WoW64 interface,
common.cpu_area returns WOW64_CONTEXT storage and common.dispatch/exception take
that packet; the unmodified x64 table still designates AMD64 contexts. The native
ARM64 mapper validates the pinned init RVA/instruction and binds 128 ordinary IAT
slots, with no auxiliary ARM64EC IAT. Public Wine context/suspension APIs are not
used to drive Raven threads; their unused imports return explicit unsupported
status. Native RtlRestoreContext aborts explicitly if reached.

RavenWow64Run reloads the selected packet and software segment state at each
entry. Dispatch and fault callbacks spill state and clear IN_JIT before the host
nonlocal stop; no ScopedJITContextLock is abandoned. Cooperative scheduling
reuses the module thread with saved packets; RAVEN_PARALLEL=1 creates M3 resident
workers with individual module TEB/TLS/context and guest FS bases. Worker teardown
calls BTCpuThreadTerm on its own pthread after stopping guest execution.

Deadline qualification found that WoW64's inline 4 KiB InterruptFaultPage is not
safe to protect independently on a 16 KiB host. The first timeout probe exceeded
its outer deadline (the Python runner killed only its child). An attempted
16 KiB-aligned field failed the Windows compiler's 8192-byte alignment limit.
The final patch extends the existing ARM64EC SuspendDoorbell field and block-entry
check to guest-window builds, exposing its address through RavenWow64Doorbell.
Controller timers and remote pauses use atomic stores, with the same exact
BRK#CAFE recognition as M3. There is no page-protection interrupt or entitlement
requirement. This narrowly changes FEXCore's existing suspend plumbing as well as
the MIT frontend; instruction/address translation remains unchanged.

Native window probing reports B=0x7000000000, size=0x100000000 and real host pages
of 16384 bytes. It commits/restores pages at guest 0x10000, 0x400000, 0x7ffe0000
and 0xffffc000, and rejects null-page/out-of-range/overflowing translations. The
probe deliberately bypasses Raven's sysconf compatibility macro, which otherwise
reports the Windows 4096-byte page size.

The initial all-FEX regression run exposed an inherited unimplemented
enter_nt_service seam with the current provisioned ntdll. The separate fix
preserves a captured syscall number in thread snapshots, checks the syscall/RET
boundary and moves R10 to RCX before using existing NT handlers. It does not
change Rosetta dispatch. A wrong-number rejection/checked-return contract covers
this seam. Earlier failed qualification runs are recorded in m4-evidence.json;
they are not included as passing results.

## Remaining limits

- Hardware AV state reconstruction/repair is qualified directly at the engine
  boundary, including a resident worker. The existing x86 process runner still
  lacks a hardware-fault-to-guest-SEH bridge. The PE32 SEH fixture qualifies
  software RaiseException, vectored exception/continue handlers and an FS:[0]
  registration handler in the existing 32-bit runtime component. It does not
  establish hardware SEH, nested unwind or C++ exception parity.
- Legacy FXSAVE packets are transported, but M4 does not qualify x87 rounding,
  MXCSR exception behavior, AVX/YMM, debug registers or full Get/SetThreadContext
  parity. Native Wine RtlWow64* context APIs and native restore are unsupported.
- Resident-worker deadline, fault repair and code-modification cases are covered;
  broad concurrent SMC races, sustained workloads and performance are not.
- Tier 0 retains M2's union of 4 KiB logical protections within 16 KiB host pages
  and explicit PAGE_GUARD rejection. There is no Windows-exact subpage isolation.
- Unix-library/graphics callbacks, full user LDT semantics, multiple module
  instances/reinitialization and Tier 1 remain outside this qualification.

There is no remaining Tier 0 placement or frontend-initialization decision
blocker. These are experimental execution contracts, not general application
or Windows parity claims.
